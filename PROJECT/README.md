# PROJECT/

## Why this exists
This is the actual multi-agent system — every domain agent, the
LangGraph pipeline that orchestrates them, guardrails, tracing,
middleware, the event simulator, and the research evaluation suite.
`backend/` is a thin HTTP shell around `PROJECT.graph.run_graph`;
`frontend/` never talks to anything in here directly.

## Folder map
| Folder | Owns | README |
|---|---|---|
| `state/` | The shared graph state schema every node reads/writes | `state/README.md` |
| `agents/` | Domain logic — inventory, forecast, supplier, KG, risk, recommendation, malfunction, allocation, shipment delay | `agents/README.md` |
| `tools/` | LangChain `@tool`-wrapped functions the LLM agents call | `tools/README.md` |
| `orchestrators/` | Builds each tool-calling sub-agent (`create_agent` + middleware) | `orchestrators/README.md` |
| `middleware/` | Custom `create_agent` middleware (guardrails, normalization, audit logging) | `middleware/README.md` |
| `guardrails/` | The underlying validation logic middleware/nodes call into | `guardrails/README.md` |
| `graph/` | The LangGraph `StateGraph` — nodes, routing, planner, checkpointing | `graph/README.md` |
| `models/` | Pydantic result models every agent returns | `models/README.md` |
| `data_loader/` | Cached DB reads + live-state tables (`tank_status`, `shipment_status`, `event_log`, `eval_results`) | `data_loader/README.md` |
| `database/` | Raw DB connections (Postgres engine, Neo4j graph) | `database/README.md` |
| `factories/` | The `create_agent` wrapper (`build_agent`) every orchestrator uses | `factories/README.md` |
| `llm/` | Model client construction (Groq) | `llm/README.md` |
| `observability/` | LangSmith tracing config | `observability/README.md` |
| `simulator/` | P5 — inject events, auto-run the real pipeline | `simulator/README.md` |
| `eval/` | P8 — research evaluation suite | `eval/README.md` |
| `scripts/` | One-off/maintenance scripts (Neo4j seeding) | `scripts/README.md` |

## Root files
| File | What it does |
|---|---|
| `main.py` | Standalone entry point (separate from `backend/main.py`) — likely a CLI/dev runner for the graph outside FastAPI. |
| `.env` | Secrets/config: `DATABASE_URL`, `GROQ_API_KEY`, Neo4j credentials, `LANGCHAIN_API_KEY`, etc. **Never commit this.** |
| `requirements.txt` | Python dependencies for this package. |
| `supply_chain.db` (+ `-shm`, `-wal`) | The SQLite database, if `DATABASE_URL` defaults to sqlite. The `-shm`/`-wal` files are SQLite's write-ahead-log — normal, don't delete manually while the app is running. |
| `graph.html` | Auto-generated by `tools/kg_tools.py`'s `visualize_subgraph()` — a pyvis-rendered Neo4j subgraph, overwritten each time someone asks a "show me the graph" question. Safe to delete; regenerates on demand. |

## Data flow, one level up from the folder READMEs
```
backend/graph_stream.py
  → PROJECT/graph/workflow.py's compiled `graph`
    → PROJECT/graph/nodes.py (one function per node)
      → PROJECT/agents/*.py (the actual domain logic)
        → PROJECT/tools/*.py (for the LLM-tool-calling sub-agents)
          → PROJECT/orchestrators/*.py (builds those sub-agents)
            → PROJECT/factories/agent_factory.py (create_agent wrapper)
              → PROJECT/middleware/*.py (guardrails, normalization, audit)
```
Every node also reads/writes `PROJECT/state/agent_state.py`'s
`SupplyChainState`, and every DB-backed table lives behind
`PROJECT/data_loader/loader.py`.
